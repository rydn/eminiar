A path that comes from a caller or from a committed file must not reach files outside the project, and a file a Claude Code `Read` deny or ask rule matches must not be read for the index or the dashboard.

- Memory names: `assertMemoryPath` in src/memory/store.ts runs at the top of write, read, edit, setMeta, rename (from and to) and remove: a valid name (assertValidName), and a file `insideMemories`. The name is the file path (relOf), so this one check covers em_remember, em_memory, the dashboard (src/ui/api.ts; src/ui/server.ts answers 400) and the CLI. `supersedes` is stored as written (`mem:`/`memory:` prefixes are supported, as in syncGraph); write marks the target superseded only when the stripped name is valid, inside the memories folder, and set or changed by this write (compared with the old header, prefix stripped). Otherwise it is a quiet no-op after the memory is saved: a bad value never becomes a path, an old header never blocks an edit, and a dashboard re-save neither rewrites the target nor undoes a status the user set on it.
- Config paths: `memories.dir` has the PROJECT_RELATIVE_PATH_RE schema pattern like `docs.manifest`. loadConfig drops an unsafe value of either key from a layer (withoutUnsafePaths over PROJECT_PATH_KEYS, stderr note), the personal layer included, so the rest of the config survives. A new project-relative path key that eminiar writes through belongs in PROJECT_PATH_KEYS.
- Symlinks: `insideMemories` requires a memory file to resolve inside realpath(memories folder), and that folder inside realpath(root). A file that is a link is resolved by its target; otherwise by its nearest existing folder (a file a write would create), with a per-call memo of folder realpaths (an lstat per file). So `.eminiar/memories` may link to another folder of the project, but a topic or file link to ~, src/ or CLAUDE.md is refused. reconcile lists a top-level link that leads out once and passes it to fast-glob's ignore (it follows links, so `x -> ~` would read all of ~), globs with deep 3 (names nest one topic; one more level is still reported), forgets rows of skipped files and leaves the files alone. The named calls throw; migrateLegacy leaves such rows in the database (listed in `skipped`); rename's mem: reference rewrite skips such files. Docs: `refuseOutside(root)` in src/index/indexer.ts is an indexPath `refuse` callback (fast-glob follows symlinks); syncPathSource also applies it to the source path itself (a refused source's previously indexed pages are deleted), and em_reindex docs uses it for its walk of the root.
- Docs `path` sources: normalize() drops an entry whose `path` fails PROJECT_RELATIVE_PATH_RE with a stderr note (probeManifestAt reports them as `outside`), and a write refuses the manifest as lossy, naming it, unless the write is removeSource of that very name (`removing`). syncSources reports such an entry on every sync and deletes its earlier pages. makeSource uses the same rule. Sync refusals land in the result's errors and `skipped`; the sync does not throw.
- Read rules: em_index and the dashboard file viewer (/api/file) use `readRefusal` (src/sandbox/file.ts): the path as written with checkRead, then, when it exists, its resolved forms with checkReadPath, worded like confinePath's refusal; ask counts as deny. em_index skips denied files under a directory through the `refuse` callback and lists them. Like em_execute_file and routing they load rules without `permissions.extraDeny`. Tests of Read rules point HOME at a temp dir (loadPermissionRules reads ~/.claude/settings.json).
- Read pattern forms (src/permissions/rules.ts readSource): resolved as Claude Code does, against `PermissionRules.root` (set by loadPermissionRules; confinePath fills in its own root; default cwd): `//x` absolute, `~/x` home, `./x` and `x/y` under the root, `/x` under the root and also the absolute `/x` (backward compatible), a slash-less name at any depth under the root, `**…` anywhere; `/**/` also matches no folder, `?` is one character, a trailing `/` names a folder, every form also covers what lies below a match; `[...]` is literal. checkRead goes through `readMatcher` (compiled once per rule list via a WeakMap, keyed by root and HOME) with a literal `needle` per rule tested by `includes` before the regex: 5000 paths x 1000 rules went from 2.3 s to 0.44 s. checkReadPath and refuseUnreadable test the path as written first and realpath only when that passes and differs.
- Leaving the index: indexPath calls `forgetFile` (every document with uri `file://<abs>`, any source) for a file `refuse` rejects, and after a directory walk prunes documents of its source under that directory whose file no longer exists; em_index does forgetFile on a refused target.
- Memories folder: when the folder itself is refused (leads out, or a dangling link) reconcile reports it and returns without forgetting rows (a checkout or link swap must not drop every memory). Dangling links under the folder are reported in `skipped` (fast-glob objectMode, onlyFiles false); `remove` may unlink a dangling link when its parent folder is inside the memories folder (unlink never touches a target).
- Not covered:
  - the startup code indexer does not check Read rules or symlinks out of the project;
  - the code passed to em_execute or em_execute_file is checked against Bash rules only and can open any file;
  - em_index still takes a path outside the project root;
  - a denied directory given to em_index as its target is refused, but files under it indexed earlier stay until a walk of a parent or a purge;
  - a docs directory walk (sync, em_reindex docs, em_index) still traverses a symlink out of the project before its files are refused, and reconcile still reads one level behind a link nested below a topic (deep 3);
  - every check is a check-then-use: a path swapped between the realpath and the read is not caught.
