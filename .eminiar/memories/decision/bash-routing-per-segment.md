Bash routing precision (branch worktree-routing-precision, v0.9.1, 2026-10-26). Ryan saw eminiar deny more Bash commands after the knowledge-routing PR (v0.9.0). Measured from the Claude Code transcripts of 2026-10-26 (5 sessions, 23 Bash calls): 17 denied (74%), all to em_execute, one session 7/7. Replaying them through `suggest()` showed the same 17, and `git log -S` showed HEAVY_BASH / TINY_BASH / the pipe rule unchanged since the initial commit: not a regression of the rules, the rules were coarse and the model started composing more compound commands. The false positives fell into three classes: pipes ending in `| head` / `| tail` / `| wc` (the output is bounded by construction), `cat` of a few small source files (what Read shows natively anyway), and compound commands that commit or write a file (`git commit … | wc -l`, `cat >> file <<EOF … npx tsc | head`).

Decision: judge a Bash line one simple command at a time (`commandSegments`: split at `;`, `&&`, `||`, newlines outside quotes, heredoc bodies removed first), and classify each with `heavySegment`:
- a segment containing a mutation (`git commit/checkout/pull/…`, `npm install`, `rm`, `mv`, `sed -i`, a `>` redirection into a file) makes the whole command native: its output is secondary and the permission prompts live in Bash;
- `git log/blame/show/shortlog` anywhere → em_history (unchanged);
- a segment is bounded when its last pipe stage is `head`/`tail` (≤ 400 lines) or `wc`, or its first stage is `head`/`tail`, `sed -n 'A,Bp'` (≤ 400 lines), `du -s`, `grep -l/-c/-q`, `git log -1`, or `cat`/`grep` over named existing files within Read's limits (200 KB total, 20 KB for data extensions); globs, variables and directories are unknowable and stay heavy;
- otherwise the old rules apply per segment: HEAVY_BASH on the first stage, or an unknown source piped into `grep|sort|uniq|jq|less`. The denial reason names the heavy segment.
Replaying the 23 recorded commands: 3 routed instead of 17 (a `git diff`, a 420-line sed range into grep, and a cd + grep -r), with no new denial.

Observability: every routed native call (Bash, Read, Grep, WebFetch, WebSearch) records a `routing` session event {tool, decision allow|annotate|deny, target, rule, why, head}; `em_stats` / `eminiar stats` print "routing (session|project): Bash 3/23 denied (13%) … denied → em_execute ×3; by rule: heavy ×2, pipe ×1", and `~/.eminiar/hook.log` gets one line per denial. The `routing` category is P4 and never in the guide, like `recall`. Suggestions carry a `rule` label (heavy, pipe, big-read, history, symbol, content-grep) for this.

Not done: Grep tool routing is unchanged; `git diff <one file>` is still heavy; a `for … do … done` loop is split at its `;` so only its body commands are judged (since 2026-11-08 with the `do` / `then` / `{` in front stripped, see below).

Side effects stay native, history and big reads only where the em_* tool can answer (branch fix/keep-side-effects-native, 2026-11-08). In enforce mode HEAVY_BASH matched `kubectl`, `docker`, `curl`, `wget`, `make` and `npm run` whole, so `kubectl delete pod x -n prod`, `curl -X POST …`, `docker rm`, `make deploy`, `npm run deploy` and `wget <url>` were denied and sent to em_execute, which has no permission prompt and skips the user's own PreToolUse hooks; `find … -delete`, `… | xargs rm` and any unknown CLI piped into grep (`ssh host 'rm …' | grep`) were routed too. Decision:
- `staysNative` (was `mutates`) judges every pipe stage, plus the commands inside `$(…)`, backticks and `<(…)` / `>(…)` (extracted from the whole line before splitting, since `&&` inside them would split the segment), after stripping shell grammar (SHELL_WORDS: `{`, `(`, `!`, `then`, `do`, `else`, `exec`, `if`, `while` …) and a runner prefix (RUNNERS, each option either valued or not so the regex stays linear — an ambiguous `-[sk]\s*\S+|-\S+` took seconds on 40 flags: `sudo` / `env` / `xargs` / `parallel` / `timeout <n>` / `nice` / `stdbuf` / `time` / `command` with their options, `nohup`, `FOO=1`) and a path (`/usr/bin/kubectl`). A stage stays native when MUTATING matches (now also git global options before the subcommand, `git clean`, `branch -d/-D/-m/-M`, `config` set/unset, `eval`, `sh|bash|zsh`, `find -delete|-exec|-execdir|-ok|-okdir`, `terraform apply|destroy|import|taint|state rm…`, `helm install|upgrade|uninstall|rollback`, `mvn deploy|install|release:*`, `gradle publish*|upload*`, `npm audit fix`; it ends in `(?![\w-])` so `git merge-base` is not `git merge`), when FOLLOWS matches (`tail -f`, `kubectl|docker … -f|-w|--follow|--watch`: em_execute would only time out), when a later stage is an interpreter reading its program from the pipe (`| python3`, not `| python3 -m json.tool`), or when the CHANGES table says the call changes something: kubectl / docker unless their subcommand past global options (VALUE_OPTS) is a read; curl with a method other than GET/HEAD, a body, form, upload, output or config file (in a cluster everything after `X` is its value, so `-sXGET` reads); wget unless it prints, or with `--post-data` etc.; `gh api` with a non-GET method, fields, or a GraphQL mutation; npx unless vitest/jest/tsc/eslint/biome/prettier without FIX_ARGS (`--fix`, `--write`, `-u`, `--update-snapshots` …); `npm run <script>`, `yarn <script>`, `pnpm --filter x <script>` unless a test/lint/typecheck/check script (not `*:fix`/`*:update`) without FIX_ARGS; `make` unless every target is such a check (HEAVY_BASH keeps `make` for those). WRITES_FILE also catches `&> f`, `cmd>f` (not `=>`, `->`, `2>&1`), tested with quoted spans blanked so `rg 'Promise<string>'` or `jq 'select(.n>3)'` is not a write. withoutHeredocs keeps the rest of the `<<EOF` line (`cat <<EOF | kubectl apply -f -`). A helper rather than one regex because a lookahead after optional flag values backtracks (`kubectl -n logs delete` would read as `logs`).
- Every em_execute route (heavy, big-read, pipe) needs every stage after the first to be a known filter (FILTERS: grep, sort, jq, head, tail, wc, cut, awk, sed, `python3 -m json.tool` …): `git diff | patch -p1`, `cat dump.sql | psql`, `curl … | python3 -c …` stay native. The pipe rule also needs a known read-only source (READ_SOURCE: `ls`, `cat`, `sed`, `ps`, `git diff|ls-files|branch|…`, `gh api|pr view|run view|…` …): an unknown first command may change something, so it stays native. Not `env`/`printenv`: em_execute runs with buildEnv's allowlisted environment, so it would answer about a different one. `helm list | grep`, `terraform plan | grep` are native now.
- em_history only when the read runs in the root's own repository: the shell's cwd moved by each `cd`/`pushd` before it and by `git -C`, under the root, with the nearest `.git` (folder or worktree file) at or above the root, not nested. A filesystem walk, no git spawn (a hook is a new process per call, so a cache would never hit); a repository with no commits reaches em_history and gets its "no commits yet" error. `--git-dir`/`--work-tree` or a `cd` only the shell can resolve (`$X`, `-`) never go there; otherwise the command is judged like any other (`cd /x && git log` → em_execute, `git -C x log` → native).
- A big Read goes to em_execute_file only if `confinePath` (what em_execute_file itself runs, with the root as a real path) accepts it: outside the root (Claude Code's saved tool outputs) or a Read deny/ask rule → native. A Read with `offset` or `limit` is a window the model chose → native.
Not done: an unknown CLI that changes something in its own segment (not piped) still lets a compound line route when another segment is heavy (`ssh host 'rm x'; git diff`); `curl -c` / `-D` (cookie or header files) and `git branch <new>` (creates a branch) are not detected. Read-only forms that are now native because they cannot be told apart cheaply: `find -exec grep`, `env | grep`, a pipe into a reader that is not in FILTERS (`| python3 -c …`, `| cat`); `stdbuf`/`time` before a heavy read leaves it native (HEAVY_BASH does not strip runners).
