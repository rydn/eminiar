Agent swarms architecture (branch feature/agent-swarms, v0.12.0, 2026-10-28; spec docs/design/agent-swarms.md). The main Claude Code session is the coordinator because subagents cannot spawn subagents. Workers are project agent files `.claude/agents/swarm-<swarm>-<role>.md` GENERATED from `.eminiar/swarm.yaml`: frontmatter emitted with the yaml lib, "---" rejected in every frontmatter value (Claude Code ends frontmatter at the first "---" anywhere), and the first body line is an `eminiar:swarm` marker with a content hash, so sync never replaces hand-written, hand-edited, unreadable or symlinked entries. Project agents, not plugin agents, because plugin agents ignore frontmatter `hooks`. The ledger (runs, tasks, workers, events, blackboard notes, spawn reservations) lives in the project SQLite DB (migration 7) behind `db.swarm`.

Hooks do the integration. PreToolUse(Agent) enforces capacity PER SWARM across all runs (live workers + open reservations) in an immediate transaction; a busy DB denies with "retry" rather than failing open. The reservation carries the Agent call's tool_use_id and is released on its PostToolUse/PostToolUseFailure. SubagentStart registers the worker and injects a knowledge brief (memories recalled per goal/task/role + memories linked to task files, history risk, hot files, project brief), capped under Claude Code's 10k additionalContext limit. There is deliberately NO task hand-off at SubagentStart: it cannot see the spawn prompt, and parallel same-role spawns cannot be told apart (two review rounds found mis-assignments with every heuristic), so the worker claims the task its prompt names. PreToolUse(em_swarm) stamps every call with caller kind/agent/session and an HMAC signature (secret ~/.eminiar/swarm.key); the server trusts only verified stamps, unverified calls are read-only. Ghost workers (no SubagentStop) are freed by SessionEnd, by finish, by em_swarm `release`, or after 15 min of silence (PreToolUse pings keep live workers fresh). Topologies are claim policies: hierarchical (role must match), mesh (anyone), pipeline (earliest unfinished stage). Opt-in: no YAML or `enabled: false` means every path no-ops, and `yaml` is required lazily so other projects' hooks pay nothing. Known limitation: worktrees of bare or separate-git-dir repositories keep their own ledger (git cannot name their main checkout).
