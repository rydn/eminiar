Model gateway / usage-insight research (branch feature/model-gateway, 2026-10-26). Four data sources exist for per-model-call depth in Claude Code, none yet read by eminiar beyond hooks:
1. Transcript JSONL (~/.claude/projects/<slug>/<session>.jsonl; subagents in isSidechain/agentId entries). Each `assistant` entry carries requestId, message.model, message.usage {input_tokens, output_tokens, cache_creation_input_tokens, cache_read_input_tokens, cache_creation.{ephemeral_5m,ephemeral_1h}_input_tokens, output_tokens_details.thinking_tokens, server_tool_use.{web_search,web_fetch}_requests, service_tier, speed (fast mode), iterations[]}, stop_reason, plus cwd, gitBranch, version, entrypoint, promptId, effort, permissionMode. One API response = several entries (one per content block) sharing requestId, so dedupe on requestId+message.id (ccusage does the same). Claude Code deletes transcripts after ~30 days, so a local warehouse is needed for history.
2. Statusline JSON (eminiar already ships `eminiar statusline`): cost.total_cost_usd (client-side list price, honours settings `modelPricing`), cost.total_api_duration_ms, context_window.{used_percentage, current_usage}, prompt_cache.{warm, ttl, expires_at}, rate_limits.{five_hour, seven_day}.{used_percentage, resets_at} (subscribers only; the only official plan-limit source), rate_limits.spend_limit behind a Claude apps gateway, prompt_id matching OTEL prompt.id.
3. OTEL export (opt-in env CLAUDE_CODE_ENABLE_TELEMETRY): metrics claude_code.{cost.usage, token.usage, session.count, lines_of_code.count, commit.count, pull_request.count, active_time.total}; events user_prompt, api_request, api_error, tool_result, tool_decision; attributes model, agent.name, skill.name, plugin.name, mcp_server.name, query_source (main/compact/subagent), prompt.id. Names are redacted to "custom"/"third-party" unless OTEL_LOG_TOOL_DETAILS=1.
4. A local proxy at ANTHROPIC_BASE_URL (only source for per-request latency, TTFT, HTTP status, 429/529, retry-after, request/response headers, bodies). Protocol rules from code.claude.com/docs/en/llm-gateway-protocol: serve /v1/messages (+ optional /v1/messages/count_tokens); forward anthropic-* headers and body fields verbatim (anthropic-beta carries the OAuth capability for claude.ai logins, stripping it gives 401); return retry-after as integer seconds; keep text/event-stream content-type; x-claude-code-session-id identifies the session. Setting only the base URL keeps the subscription login working. Managed `allowedProviders` can forbid a custom endpoint.
Comparable tools surveyed: ccusage (daily/weekly/monthly/session/blocks, cost modes auto/calculate/display, 5h billing blocks with burn rate), Claude-Code-Usage-Monitor (plan limits, P90, provenance/confidence labels, statusline capture of official rate_limits, warehouse), ccstatusline (cache hit/read/write widgets, compaction counter, cost/hour), tokscale (10 TUI views, group-by, subagent roll-up, leaderboard), wlog/toolytics/sniffly/ccq (transcript readers: tool rankings, accept/reject, heatmap, error breakdown, DuckDB over JSONL), claude-code-otel (Grafana stack), ccflare/claude-code-router (local proxies: request log, routing rules, fallbacks, account pools), context-mode Insight (hosted; events uploaded; blockers/error loops/risks by person and team; composite scores), LiteLLM/Helicone/Langfuse/Portkey (spend per key/user/team, budgets, alerts, pricing tiers above 200k input, zero-cost flagging).
