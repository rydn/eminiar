Config layering rules (swarm run 20261109-0b73c5, task #87, branch fix/config-layering, 2026-11-09). (1) graph.exclude, permissions.extraDeny and sandbox.disabledLanguages (ADDITIVE_LISTS in src/config.ts) add up instead of replacing: built-in default, then the personal config, then the project file, then env, each entry kept once (mergeLayers). A project file can add a deny rule but cannot remove a personal one. Only graph.exclude accepts "!<glob>", and it removes ONLY a built-in default, never an entry the user wrote. A personal entry that merely equals a built-in default does not count as the user's, because every install before PR #56 wrote a frozen copy of all 13 defaults into ~/.eminiar/config.json (src/install/install.ts frozenDefaults()); protecting those entries made a team's "!**/vendor/**" silently do nothing (found by re-review #113, fixed in task #121). A personal entry that is NOT a default (e.g. "**/secret-dir/**") cannot be removed by a project "!". In the security lists "!" is a literal, so a cloned repo cannot weaken them. All other lists (graph.include, index.docs, envAllow) still replace. (2) A schema error costs only the layer that holds it. loadConfig parses the merge once. If that fails, it parses each layer alone over the defaults, drops the invalid ones with the stderr note "invalid config in <file>, ignoring it", and reparses. It falls back to the defaults only if the rest is still invalid. A layer that is valid alone but fails on top of earlier layers (e.g. adjudicator.weights.features over its 64-key cap after merging) loses only the fields the zod error names (withoutPaths), with a note naming the file; an earlier layer is never blamed (review #89, task #103). A wrong-typed value in an additive list drops that layer with a note instead of silently turning the list back into replace (#104). (3) Unknown keys are stripped by zod and never invalidate a layer, so an older eminiar still loads a newer config. Doctor (not loadConfig) is where typo warnings belong. memories.dir containment is done by PR #45 (withoutUnsafePaths), not by this change.
