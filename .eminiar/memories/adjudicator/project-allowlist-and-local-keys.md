Adjudicator project-layer allowlist and local-key rule (task #32, swarm run 20261104-483f39, 2026-11-04, branch feature/adjudicator; implements constraint adjudicator/project-layer-trust-boundary rules 1 and 3). src/config.ts: PROJECT_ADJUDICATOR_KEYS = enabled, mode, surfaces, promptMode, minPromptChars, tiers, weights, apply, advice, embedding, learning, cache. projectLayer() keeps only those from <root>/eminiar.config.json; provider, typesafe, openai (preset/baseUrl/model/price — price matters because a 0 price bypasses budget.dailyUsd), keyEnv, remoteConsent, privacy, budget, timeouts, breaker come only from ~/.eminiar/config.json + EMINIAR_* env. Exception: a project section containing a key-like field is passed whole so the secret check still rejects the config (defaults, adjudicator off). Exports droppedProjectAdjudicatorKeys(raw) and projectAdjudicatorWarning(root) (one line; wired in by task #46: doctor check "adjudicator project config" (ok:true, shown even while off), `adjudicator status` warning line + `projectIgnored` in --json, and `projectIgnored` in the dashboard overview payload of src/ui/adjudicator-api.ts). `key status`, `key set`'s precedence note and the install/onboarding key step use keyFor() (via resolvedForKey(id) in cli.ts), so they never report an env key for a loopback target. Keys: resolveKey(id,{fileOnly}) skips every env var; src/adjudicator/config.ts keyFor(r, env) passes fileOnly = !r.configuredRemote and is the ONLY way providers (openai.ts, typesafe.ts) and currentKeyFingerprint get a key, so a loopback target gets only a key-file entry for its own id, never keyEnv / provider env / EMINIAR_ADJUDICATOR_KEY. Tests that configure the provider must write the adjudicator section to $EMINIAR_HOME/config.json, not the project file (tests/unit/adjudicator-hooks.test.ts configure() does). Regression tests: tests/unit/adjudicator-config.test.ts "project layer trust boundary (#32)" and tests/unit/adjudicator-providers.test.ts "no env key for a loopback provider (#32)".

Update 2026-11-08 (branch fix/adjudicator-project-trust, todo adjudicator/project-layer-mode-apply-tiers, review #109): PROJECT_ADJUDICATOR_KEYS = enabled, surfaces, promptMode, minPromptChars, weights, advice, embedding, learning, cache. mode, tiers and apply are personal-only, because apply mode with apply.floor/ceiling or a one-tier ladder let a cloned repo put every subagent on haiku (or floor them at fable). Exception: projectKeeps(adj, k) keeps `mode: "advise"` from the project file (more conservative only). projectLayer and droppedProjectAdjudicatorKeys both go through projectKeeps; an untrusted personal file gets the same cut. A too-long tiers ladder in the project file is now dropped (warning) instead of invalidating the whole config. Not changed: weights (tierCenters can still lean the verdict inside the personal floor..ceiling) and EMINIAR_ADJUDICATOR_MODE. Known: doctor's "adjudicator config" check (adjudicatorDoctorChecks in src/adjudicator/cli.ts) still validates the raw project section against the full schema, so a project tiers/mode value that loadConfig drops can still fail doctor, as other dropped keys already do. Tests that need apply mode or apply.* must write them to $EMINIAR_HOME/config.json (tests/integration/adjudicator.test.ts globalConfig), like the provider.
